# ADR-001: Absorb Branchlet Core Worktree Operations into Mat

## Status

Accepted

## Date

2026-05-19

## Context

Mat currently depends on the external `branchlet` CLI (Node.js) for git worktree CRUD operations (create, delete, list). This creates a dependency chain: users must install Node.js + branchlet before using mat, adding setup friction and an external point of failure. The dependency is used exclusively for three operations that can be performed by shelling out to `git worktree` directly.

Additionally, mat does not support a no-worktree mode (branch-only workflow), has no configuration file, and hard-requires tmux.

## Decision

Absorb branchlet's core worktree operations into mat by replacing `branchlet` CLI calls with direct `git worktree` commands. Introduce three new capabilities:

1. **No-worktree mode** (`--no-worktree` flag): Creates a branch with `git checkout -b` and a named stash guard (`git stash push -m "mat:auto:<branch>"`) to protect uncommitted changes. Always prints a disclaimer that this is not equivalent to worktree isolation.

2. **TMUX auto-detection**: Check `$TMUX` environment variable to automatically use tmux when inside a session. Support `--use-tmux` flag for explicit opt-in outside tmux. When neither is available, open a new shell tab/process in the worktree directory.

3. **TOML configuration file** (two-tier): Global `~/.config/mat/config.toml` with project-local `.mat.toml` overrides. Typed structs via `serde::Deserialize`. Local config overrides global for conflicting keys.

4. **Branch deletion on close**: Configurable (`delete_branch` setting), defaulting to YES with an explicit confirmation prompt during close mode.

V1 scope is limited to core worktree CRUD. File copying, post-create hooks, shell integration, TUI, and worktree path templating are explicitly out of scope.

## Alternatives Considered

### Alternative 1: Use `git2` Rust crate instead of shelling out

- **Description**: Use the `git2` crate for native Rust git operations
- **Pros**: No git binary dependency; potentially faster; no process spawn overhead
- **Cons**: `git2` does not expose `git_worktree_add/remove` in its safe API; would require unsafe FFI; complex C dependency (libgit2); all competitor tools shell out to `git`
- **Why rejected**: The safe Rust API doesn't cover worktree creation/removal; shelling out is the industry standard approach

### Alternative 2: No-worktree as graceful exit only

- **Description**: When user opts out of worktree, print "Please use worktrees for full mat value" and exit
- **Pros**: Honest UX affordance; no stash guard complexity; no risk of data loss
- **Cons**: Reduces utility for repos where worktrees can't be used (disk space, monorepo size, CI environments)
- **Why rejected**: The user explicitly requested no-worktree mode as a feature; it can be implemented safely with named stashes and clear disclaimers

### Alternative 3: TMUX flag-only in V1 (no auto-detect)

- **Description**: Only support `--use-tmux` flag; require explicit opt-in for tmux integration
- **Pros**: Fewer code paths to test; simpler behavior; no environmental surprises
- **Cons**: Every invocation inside tmux requires remembering the flag; contradicts "just works" philosophy; `$TMUX` detection is trivial
- **Why rejected**: One `if` statement for `$TMUX` detection is minimal complexity for meaningful UX improvement

## Consequences

### Positive

- Eliminates Node.js dependency; mat becomes a single Rust binary
- Worktree operations become first-class, testable, and configurable
- Two-tier TOML config provides sensible defaults with per-project overrides
- No-worktree mode enables mat usage in constrained environments
- TMUX auto-detection reduces friction for the primary use case

### Negative

- Maintaining git worktree edge cases (locked worktrees, detached HEADs, bare repos) falls on mat instead of branchlet
- Named stash guard adds complexity to the no-worktree path
- Two-tier config requires a merge strategy and validation logic
- `main.rs` needs modularization before adding config (current 505-line monolith)

### Risks

- **Stash collision/conflict**: Mitigated by named stashes with `mat:auto:` prefix; if pop fails due to conflicts, error message must guide user to `git stash list`
- **Branch deletion safety**: Mitigated by confirmation prompt; user must explicitly confirm deletion; `git reflog` provides 90-day recovery
- **Edge cases from branchlet**: Branchlet handles corrupted worktrees, submodule handling, and bare repos; mat V1 may hit these and need incremental fixes
